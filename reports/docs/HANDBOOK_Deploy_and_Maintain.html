01What the system does

Read this once, then never again

EPAL holds an environmental discharge licence for every wastewater treatment plant. Those licences arrive as PDFs from the Portuguese authorities, and each one contains the limits the plant must respect, how often it must be sampled, and when the licence expires.

Reading those PDFs by hand is slow and easy to get wrong. This system does it automatically: you drop a PDF into a folder, and a few minutes later the dashboard knows about it.

The journey of one licence

StageWhat happensWhere it ends up
You drop the PDF You put the file in the correct inbox folder Drop_New_Licenses\
The system reads it It finds the tables in the PDF and pulls out the limits, sampling frequencies and dates extraction_JSON_…\
It checks its own work Anything doubtful is flagged rather than accepted silently qa_report.xlsx
It files the licence Good ones join the master workbook; problem ones are set aside for a person master_….xlsx / data\review\
It archives the PDF The original moves to the archive — one copy, never two data\pdfs\NEW\
The dashboard updates You press Refresh in Power BI and the new licence appears EPAL_Licencas_Dashboard

Two kinds of licence

You will see two names everywhere. They are two different licensing regimes, and a plant can hold one or both:

  • TUA — Título Único Ambiental, the newer, consolidated permit.
  • LURH — Licença de Utilização dos Recursos Hídricos, the older regime.

They are processed separately because the documents look completely different, which is why you will see a pair of everything — two inboxes, two buttons, two master workbooks.

02Before you set up a laptop

Five minutes of checking saves an afternoon

Confirm all four before you start. Each one causes a different failure later.

CheckWhy it matters
Windows, not Mac The system is built for Windows. It will not run on a Mac.
Power BI Desktop is installed Needed to open the dashboard. Free from the Microsoft Store.
The folder has finished syncing The single most common cause of “it does not work”. The OneDrive icon must be a steady green tick — not spinning arrows. There are around 11,000 files; on a slow connection this takes a while.
At least 2 GB free disk space The folder is about 1 GB and Power BI needs room to work.
The path length trap

Windows refuses to open files whose full path is longer than 260 characters, and the folder already uses 146 of them. If the shared folder ends up too deep on the laptop, some files simply will not arrive — with no error message at all.

This is why the folder must be added with “Add shortcut to OneDrive” on the project folder itself, never by syncing the whole document library. The check in step 5 below confirms it.

03Setting up a laptop

Once per computer · about 15 minutes, mostly waiting

Nothing gets installed and no administrator rights are needed. The system carries its own copy of the software it needs, inside the folder.

Add the folder to this laptop

Open the team’s SharePoint in a browser, go to the Licences project folder, and choose “Add shortcut to OneDrive”.

Do not use “Sync” on the whole library — that creates a much longer path and files start disappearing silently.

Wait for it to finish arriving

Watch the OneDrive icon in the taskbar until it is a steady green tick. Around 11,000 files have to come down. Starting before this finishes is the most common reason setup fails.

Double-click Automation files\CONFIGURAR_ESTE_PC.bat

It runs five steps and prints what it is doing:

  • finds the project’s own Python;
  • pins it to the disk, so OneDrive stops emptying it later;
  • confirms every library the system needs actually loads;
  • writes this laptop’s own settings file;
  • points the dashboard at this laptop’s data.

It must end with CONFIGURAÇÃO TERMINADA.

Close Power BI first if it is open

Step 3 edits the dashboard file. If Power BI has it open, it will overwrite the change when it saves. Close Power BI, then run the setup again.

Confirm the laptop is genuinely ready

Open the folder, hold Shift, right-click in an empty area, choose Open PowerShell window here, and run:

runtime\python\python.exe src\_verificar_migracao.py

It must print TUDO PRONTO. If it prints PROBLEMA, the line underneath says exactly what to fix.

Open the dashboard once

Open reports\EPAL_Licencas_Dashboard\EPAL_Licencas_Dashboard.pbip, wait for it to load, and press Refresh. The first load takes a few minutes. The licence count should match what colleagues see.

What the setup actually changed

Two things live outside the shared folder, on this laptop only: a small settings file in %LOCALAPPDATA%\EPAL, and a shortcut at C:\EPAL\powerbi pointing at this laptop’s copy of the data. That shortcut is why the dashboard works for everyone at once instead of breaking each time a different person opens it.

04Day-to-day: adding a licence

The only routine task

Put the PDF in the right inbox

The two regimes have separate inboxes and it matters which you use:

Drop_New_Licenses\new_TUA_licences\ ← TUA certificates Drop_New_Licenses\new_LURH_licences\ ← LURH licences

You can drop several at once.

Double-click the matching button

Automation files\PROCESSAR_AGORA.bat Automation files\PROCESSAR_AGORA.bat

A black window opens and reports each licence as it goes. Leave it until it says DONE. Expect roughly 40 seconds per TUA certificate; LURH licences are much quicker.

Read the result

Only two outcomes matter:

  • OK  the licence is in the master and the PDF has moved to the archive.
  • Review  the PDF stayed in data\review\ with a .txt beside it saying, in plain language, what went wrong.

Refresh the dashboard

Open the dashboard and press Refresh. Until you do, it shows yesterday’s picture.

Only one person at a time

If a colleague is already running an extraction, yours will stop immediately and tell you who is running it. That is deliberate — two people writing to the master workbook at the same time would erase each other’s licences. Wait for them to finish and run it again.

If a licence lands in review

Open the .txt file next to the PDF. It names the problem. The most common ones are harmless:

What the note saysWhat it meansWhat to do
filename not in the expected pattern The file name does not follow the usual convention, so the dates could not be cross-checked Nothing. The licence was still read correctly.
the master workbook is open/locked in Excel Someone had the master open, so the data was parked in a side file Close Excel and run the button again. The parked data is picked up automatically.
no discharge conditions were extracted The system could not find the limits table — often an older document format Check the PDF yourself. If the table really is there, send it to whoever maintains the system.
extraction crashed The file could not be opened at all — possibly damaged or not a real PDF Open the PDF yourself to confirm it is readable, then ask for help.

05Using the dashboard

Power BI · six pages

Open reports\EPAL_Licencas_Dashboard\EPAL_Licencas_Dashboard.pbip and press Refresh whenever you want current numbers. The dashboard never updates by itself.

Opening the original PDF

On the Geral page there is a button marked Abrir licença. Select exactly one licence first — click a row in the table at the bottom left, and check the Total de licenças tile shows 1. Then hold Ctrl and click the button.

The button greys itself out when nothing is selected, or when several licences are, because “open the licence” has no meaning for three at once.

This button needs one extra thing today

Power BI can only open web addresses, not files on a disk. Until the archive is reachable over the network, the PDFs are served by a small helper: double-click Automation files\SERVIDOR_PDFS.bat and leave that window open while you use the dashboard. Close it and the button stops opening PDFs.

This is temporary. Once the archive sits on SharePoint the helper is no longer needed — the person maintaining the system changes one line and it works for everybody, including in a published report.

06Who does what

Agree this once, as a team

Most of the system is safe for anybody to use. Three things need a named owner, because doing them twice causes damage.

TaskWhoWhy it needs an owner
Adding licences, reading the dashboard Anyone Protected against clashes automatically.
The automatic watcher (Automation files\register_watch_task.bat) One laptop only It processes the inboxes by itself. Two laptops doing that can corrupt the master workbooks. Pick one machine that is usually on.
Reinstalling the portable Python One person Downloads about 150 MB into the shared folder. Only needed once, ever.
Editing the dashboard layout One person at a time Power BI saves the whole page. Two people editing means one silently loses their work.

07Regular maintenance

Four checks · none takes more than a minute

These are health checks. Each one prints a plain answer and changes nothing, so they are safe to run whenever you are unsure.

Every month

Does the dashboard hold every licence in the archive? runtime\python\python.exe src\_verificar_cobertura.py Which licences are missing information? runtime\python\python.exe src\Common_Code_PowerBI\missing_data_report.py

The second writes an Excel file to outputs\reports\ listing exactly which licences are missing which fields.

If the dashboard total looks wrong

The dashboard and the master workbook are built from different places and can drift apart. This finds and fixes it:

Show what is missing (changes nothing) runtime\python\python.exe src\Extraction_Code_LURH\sync_master_com_json.py Actually add it runtime\python\python.exe src\Extraction_Code_LURH\sync_master_com_json.py --aplicar

Then rebuild the dashboard data:

runtime\python\python.exe src\Common_Code_PowerBI\make_powerbi_all.py

Before sharing the dashboard with anyone new

runtime\python\python.exe reports\validate_project.py

It confirms the dashboard file is not damaged. It must end with tudo válido.

Backups

The master workbook is copied to master_….bak.xlsx before every change, and SharePoint keeps its own version history. To undo a bad run, restore the .bak file — or use Version history in SharePoint, which goes back much further.

When you need to ask for help

Run this first and send the text it prints. It answers most questions before they are asked:

runtime\python\python.exe src\epal_config.py

Also useful: the log for the day, in %LOCALAPPDATA%\EPAL\logs on your own laptop. It records every licence processed and every problem found.

09Five rules that protect the data

Each one exists because breaking it has already cost someone work

Never run the automatic watcher on two laptops

Two machines processing the same inbox can write to the master workbook at the same time and corrupt it. One nominated laptop only.

Close Excel before running an extraction

Nothing is lost if you forget — the data is parked safely and picked up next time — but the licence will not reach the dashboard until you do.

Close Power BI before running the setup

Power BI rewrites the dashboard file when it saves, and will undo the setup without warning.

Never edit the master workbooks or the dashboard data by hand

Everything in data\powerbi\ and every master_….xlsx is rebuilt from the PDFs. A manual edit disappears at the next run, and you will not be told. Fix the PDF or ask for the code to be changed.

Wait for the green tick before doing anything

More reported faults come from a half-synced folder than from every other cause combined.
