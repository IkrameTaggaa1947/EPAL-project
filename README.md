# EPAL — Licence Extraction System

Reads Portuguese environmental discharge licences and turns each one into a
structured, validated table that feeds a Power BI compliance dashboard.

Two regimes, one system:

| | **TUA** | **LURH** |
|---|---|---|
| Document | Título Único Ambiental (SILIAMB) | Licença de Utilização dos Recursos Hídricos (APA) |
| Code | `src/Extraction_Code_TUA/` | `src/Extraction_Code_LURH/` |
| Master | `master_tua.xlsx` + `master_all_sections.xlsx` | `master_lurh.xlsx` |
| Key | `Nº TUA` | `Nº Licença` |

Both read each certificate by its **table structure** — the ruled tables are read
directly, columns are matched by **header name** (not pixel position), sections are
located by their **marker text**, and **every field is verified** before it is
accepted. This is robust to layout differences between certificates and flags
anything doubtful instead of failing silently.

> **Operators:** you want [`LEIA-ME_PRIMEIRO.txt`](LEIA-ME_PRIMEIRO.txt), not this
> file. It is in Portuguese and covers everything you need to run the system.

## Setup

**Nothing to install.** The project carries its own portable Python in
`runtime/python`, so no one needs Python on their laptop and no admin rights are
required.

| Situation | What to double-click |
|---|---|
| The portable Python does not exist yet (once, on a PC with internet) | `INSTALAR_PYTHON_PORTATIL.bat` |
| Setting up a new laptop | `CONFIGURAR_ESTE_PC.bat` |
| Power BI says the data source is missing | `ATUALIZAR_POWERBI.bat` |

`CONFIGURAR_ESTE_PC.bat` writes this machine's settings to
`%LOCALAPPDATA%\EPAL\epal.local.ini` (outside the shared folder, so each PC can
differ) and points the Power BI `DataFolder` at this machine's copy.

To see what a given machine resolved — useful when helping someone remotely:

```bash
runtime\python\python.exe src\epal_config.py
```

Interpreter search order (`src/_find_python.bat`): portable `runtime/python` →
a machine-local venv in `%LOCALAPPDATA%\EPAL\venv` → an installed `python` → `py`.
Needs Python 3.13.x, because the bundled libraries are cp313 wheels.
Dependencies are pinned in [`requirements.txt`](requirements.txt): PyMuPDF (`fitz`),
pandas, openpyxl, requests, pytest.

## Usage

**A folder of certificates (the normal way):** drop PDFs into
`Drop_New_Licenses/new_TUA_licences` (or `new_LURH_licences`), then double-click
`Automation files\PROCESSAR_AGORA.bat` (or `PROCESSAR_AGORA.bat`). Each PDF is extracted,
quality-checked and added to the master, then filed into the archive at
`data/pdfs/NEW/<regime>/`. Only the ones that failed or need a look stay behind,
in `data/review/`, each with a plain-language note — so the review folder is a
worklist, not a pile.

The project never keeps a second copy of a PDF it has already read: the data is
in the master, the JSON and the per-file workbook, and the PDF itself lives once,
in the archive.

**Hands-off:** double-click `watch_all.bat` and leave it open,
or register the background watcher for both regimes at once:
`src\automation_of_extraction\register_watch_task.bat`.

> Register the automatic watcher on **ONE** computer only. The folder is shared:
> two machines processing the same PDFs can corrupt the master workbooks. The
> watcher keeps a lock in `src/automation_of_extraction/data/watch_lock.json` as a
> tripwire, but registration is inherently per-machine.

**One certificate (command line):**

```bash
runtime\python\python.exe src\Extraction_Code_TUA\extract_tua.py "path\to\certificate.pdf"
```

**Rebuild the dashboard feed by hand** (the pipeline already does this after each
batch):

```bash
runtime\python\python.exe src\Common_Code_PowerBI\make_powerbi_all.py
```

Then open `reports\EPAL_Licencas_Dashboard` and click **Atualizar**.

## What it produces

Two levels — the **full extraction** (every section) and the **Power BI feed**
(only what the dashboard needs):

- `<name>_extracted.xlsx` — per-certificate detail: a **Resumo** identity card plus
  one sheet per section, generically dumped so nothing is dropped.
- `master_all_sections.xlsx` *(TUA)* — the same, consolidated: one sheet per
  section with every certificate stacked and keyed on `Nº TUA`.
- `master_tua.xlsx` — the curated **Power BI star schema**, 5 linked sheets
  (Licenses · Conditions · Autocontrolo · Legislacao · Avaliacao), upserted.
- `master_lurh.xlsx` — the LURH equivalent, 9 sheets (the five above plus
  Equipamento · MeioRecetor · CondicoesTexto · Comunicacoes), keyed on `Nº Licença`.
- `data/powerbi/` — TUA and LURH **merged and enriched**, one `.xlsx` per model
  table. **This is what Power BI reads.**
- `qa_report.xlsx` — one row per certificate with its verdict (**OK / FAILED**),
  whether it reached the master, and why not if it did not.

## How it works (short version)

```
PDF → read ruled tables (one pass) → split into sections by marker (row-level,
page-break-aware) → match columns by name, resolve legend references, verify every
field (incl. filename cross-check) → write the per-file workbook → upsert the
masters ONCE PER BATCH → export the enriched Power BI feed.
```

A PDF is archived into `data/pdfs/NEW/<regime>/` only when its rows are genuinely in the
master. If the master is open in Excel the batch is diverted to
`<master>.PENDING.xlsx` and the PDFs stay in `data/review/`; the next run folds
that workbook back in automatically (`Common_Code_PowerBI/pending.py`).

## Tests

```bash
runtime\python\python.exe src\Extraction_Code_TUA\test_extraction.py
```

Same for `Extraction_Code_LURH`. They run against the frozen `*_extracted.json`
baselines rather than re-parsing PDFs, so they are deterministic. `pytest` works
too. Two more self-checks worth knowing:

```bash
runtime\python\python.exe src\Common_Code_PowerBI\pending.py
runtime\python\python.exe reports\validate_project.py
```
